# create-bonesmith

Scaffold a ready-to-build React 19 repo, either a client-side app or a publishable component library with Storybook. The generated repo also includes a `.kiro/` setup (steering, agents, MCP servers) that matches the stack you picked.

```sh
npm create bonesmith@latest my-app
```

The CLI asks for the project type, toolchain, routing, state, UI library, styling and package manager. Then it:

1. writes the project into `my-app/`,
2. runs `git init` and installs dependencies (every version is pinned exactly),
3. makes an initial commit,
4. runs `build`, `lint` and `test` once to check the result.

If a step fails, the CLI prints the exact command to re-run and keeps the project.

You need Node.js 24.11 or newer, and git.

## Usage

```sh
npm create bonesmith@latest [name] -- [flags]
pnpm create bonesmith [name] [flags]
yarn create bonesmith [name] [flags]
bun create bonesmith [name] [flags]
```

Any choice you don't pass as a flag is prompted. With `--yes`, the CLI uses the defaults instead and never prompts, which suits CI and scripts:

```sh
npm create bonesmith@latest my-app -- --yes --routing tanstack-router --state zustand --ui shadcn
npm create bonesmith@latest my-lib -- --yes --type library --ui mui --styling css-modules --pm pnpm
```

- `--styling css-in-js` can't be combined with `--ui mui`.

Every project uses TypeScript in strict mode, Vitest with React Testing Library, git, and `.kiro/`.

## Library mode

`--type library` generates an ESM-only component package:

- It is built with `vp pack` (Vite+) or Vite library mode. Output is `dist/index.js` and `dist/index.d.ts`, plus `./styles.css` when the styling option emits CSS.
- `react` and `react-dom` are peer dependencies, as are MUI and Mantine when you pick them.
- Storybook is always included. Stories run as Vitest browser tests (Playwright Chromium) as part of `test`, and `build-storybook` builds the static site.
- Routing and state aren't used; passing `--routing` or `--state` is an error.

## What `.kiro/` contains

- `steering/`: `product.md`, `tech.md`, `structure.md` and `testing.md`, plus one file per chosen option, such as `routing.md`, `styling.md` or `ui.md`.
- `agents/`: `reviewer` and `feature-builder`, plus an expert for each chosen option, such as `toolchain-expert` or `ui-expert` (`library-expert` and `storybook-expert` for libraries).
- `settings/mcp.json`: MCP servers for the chosen layers, each pinned to a version.

Options you didn't choose add nothing.

## Development

```sh
npm ci
npm run build           # src/ -> dist/
npm run typecheck
npm run lint
npm test                # unit, render snapshots, template lint (no network, no processes)
npm run lint:templates  # template lint only: every combination rendered in memory
npm run test:matrix     # real scaffold + install + build + lint + test (slow; needs pnpm, yarn, bun)
MATRIX_COMBO=app-vp-shadcn,lib-vp-mui npm run test:matrix
npm run readme          # regenerate the flags block above
npm run check:pack      # check the npm tarball file list
```

To try the CLI locally, run `npm run build`, then `node /path/to/bonesmith/dist/index.js my-app` from an empty directory.

Every option is a folder under `templates/<axis>/<option>/`, containing a `layer.json`, files and Kiro content. Adding an option means adding a folder; the core code doesn't change. Version pins and their reasons are listed in [`templates/PINS.md`](templates/PINS.md).

## Releasing

Releases are published from CI only. Push a `v<version>` tag that matches `package.json`. `release.yml` then runs the full matrix for that commit, checks the tarball, and runs `npm publish --provenance`.
